# Samsung Digital Content Plan — AI Agent

Автоматизация мастер контент-плана: пересчёт дедлайнов по правилам (не единым флэт-правилом),
поиск конфликтов и рисков, наглядный календарь, недельный дайджест для менеджера.

## Что делает

1. Читает `samsung-digital-content-plan-template.xlsx` (все 4 вкладки: контент-план, правила дедлайнов, каналы/назначения, трекинг).
2. Пересчитывает дедлайны **по правилам своего типа кампании** (Промо-запуск / Always-on / Медийка / Retail support / Маркетплейс) — вместо единого правила −14/−7/−3, которым были посчитаны дедлайны в исходном файле.
3. Сдвигает дедлайн на предыдущий рабочий день, если он падает на выходной.
4. Добавляет +1 день на согласование, если назначение кампании — дистрибьютор (Technodom / Sulpak / Mechta / Evrika).
5. Прогоняет 6 проверок из вкладки «Трекинг» + правило покрытия моделей из вкладки «Каналы и назначения»:
   - просроченные дедлайны,
   - дедлайны в ближайшие 7 дней,
   - кампании без креатива при близком старте,
   - перегруз недели (>4 запуска),
   - медийка без перформанс-поддержки той же модели,
   - модели без покрытия маркетплейсом/дистрибьютором.
6. Отдельно подсвечивает, где именно исходный файл посчитал дедлайн неверно (флэт-правило vs правило по типу).

## Как менеджер работает с этим каждый день

Открой **`app.html`** (двойной клик, работает в любом браузере, сервер не нужен) — это и есть
рабочее приложение, а не просто отчёт:

- Видно весь контент-план, календарь, дайджест и риски одним экраном
- Менеджер **добавляет новую кампанию всего по 3 полям**: модель, тип, дата старта —
  агент сам подбирает канал, назначение и формат креатива по матрице «канал → назначение»
  (с ротацией между дистрибьюторами/маркетплейсами, чтобы покрытие не проседало на одном партнёре)
- Дедлайны и конфликты пересчитываются мгновенно при любом изменении — статус, дата, новая кампания
- Данные сохраняются в браузере автоматически; кнопки «Экспорт/Импорт JSON» — на случай
  переноса на другой компьютер или как резервная копия

`engine.py` — это тот же набор правил, но как воспроизводимый пакетный пайплайн (запускается
на файле целиком, удобно для CI/автоматизации). `app.html` — интерфейс на каждый день.

## Как запустить

```bash
pip install openpyxl
python engine.py
```

Меняете `INPUT_PATH` в начале `engine.py` на файл следующего месяца — весь пересчёт и все проверки
берутся из самого файла (правила, матрица каналов), а не захардкожены, так что скрипт отработает
на новых данных без переделки.

## Что на выходе

- `content-plan-corrected.xlsx` — тот же контент-план с пересчитанными датами и подсветкой (красный = просрочено, жёлтый = дедлайн на этой неделе)
- `calendar.html` — интерактивный календарь по неделям (открывается в браузере, без сервера)
- `conflict-report.md` — отчёт проверок с приоритетами
- `weekly-digest.md` — дайджест для менеджера: что горит / что делать на неделе / где дыры
- `output.json` — сырые данные пересчёта (используются календарём)

## Используемые инструменты

- Claude (Sonnet) — вся логика, парсинг Excel, промпт-инжиниринг структуры проверок
- Python (openpyxl) — чтение/запись Excel, вся бизнес-логика пересчёта
- Vanilla HTML/JS — интерактивный календарь (без сборки, открывается напрямую)

## Использованные промпты (сжато, по сути)

1. «Прочитай оба тестовых задания и Excel-файл, дай план: что автоматизируем, с чего начать» — разбор требований.
2. «Построй движок: читает Excel, применяет ПРАВИЛА ПО ТИПУ кампании (не единое правило) из вкладки
   "Правила дедлайнов", сдвигает дедлайн на выходных на предыдущий рабочий день, +1 день если
   назначение — дистрибьютор. Прогони 6 проверок из вкладки "Трекинг" + правило покрытия моделей.
   Явно покажи, где исходный флэт-расчёт (−14/−7/−3) разошёлся с верным».
3. «Построй HTML-календарь по неделям на основе output.json движка — без React, один файл,
   открывается без сервера, данные не хардкодить».
4. «Сгенерируй недельный дайджест по трём вопросам: что горит / что делать на неделе / где дыры —
   коротко, с приоритетами, не выгрузка всей таблицы».

## Найденная ошибка в исходном файле

Дедлайны в `samsung-digital-content-plan-template.xlsx` были посчитаны единым правилом −14/−7/−3
для всех 12 кампаний. По вкладке «2. Правила дедлайнов» у пяти типов кампаний разные сроки
(например, «Медийка» требует −21/−10/−5, а не −14/−7/−3 — на видеопродакшен нужно больше времени).
После пересчёта по верным правилам 8 из 12 кампаний получили другой (более ранний) дедлайн брифа —
подробности в `conflict-report.md`, раздел «Расхождение с исходным файлом».
